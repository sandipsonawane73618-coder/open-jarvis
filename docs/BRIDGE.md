# Open Jarvis CLI Bridge

The Termux CLI bridge uses a random authentication token and a TCP listener bound
only to IPv4 loopback (`127.0.0.1`). The app does not listen on Wi-Fi, mobile
data, or other network interfaces.

## Quick Start

1. Start Open Jarvis and enable the floating Overlay Service.
2. In Termux, install the socket client:

```bash
pkg install socat
```

3. Install the CLI helper:

```bash
cp scripts/jarvis.sh $PREFIX/bin/jarvis
chmod +x $PREFIX/bin/jarvis
```

## Usage

```bash
jarvis "open whatsapp"
jarvis status
jarvis history
jarvis providers
jarvis memory
```

The helper checks both provider authorities:
`content://com.openjarvis.bridgeconfig/config` (release) and
`content://com.openjarvis.preview.bridgeconfig/config` (preview). It reads the
dynamic loopback port and token from the running variant. The provider returns
those values only to the Open Jarvis app UID, the installed Termux app UID, or
Android's ADB shell UID.

## Protocol

Request:

```json
{"cmd":"open whatsapp","requestId":"abc123","token":"<bridge-token>"}
```

Response:

```json
{"requestId":"abc123","status":"done","result":"success"}
```

Status values are `progress`, `done`, and `error`.

## ADB forwarding

From a host computer connected with ADB:

```bash
# Use the provider authority matching the installed app variant:
adb shell content query --uri content://com.openjarvis.bridgeconfig/config
# For the preview APK, use:
adb shell content query --uri content://com.openjarvis.preview.bridgeconfig/config
```

Read the returned `port` and `token`, then forward the reported port:

```bash
adb forward tcp:5000 tcp:<reported-port>
```

Send a request containing the returned token:

```bash
printf '{"cmd":"status","requestId":"1","token":"<bridge-token>"}\n' | nc 127.0.0.1 5000
```

## Security model

- The TCP listener binds explicitly to `127.0.0.1`, not `0.0.0.0`.
- Every request must contain a random 256-bit token generated by Open Jarvis.
- The token is stored in the app's private preferences.
- The exported config provider checks the actual Binder caller UID before
  returning the token; only the app UID, installed `com.termux` UID, and
  Android shell UID (ADB) are trusted.
- Requests are limited to 8 KiB, commands to 2,000 characters, request IDs to
  128 characters, and the loopback bridge to 10 requests per rolling second.
- Token comparison uses a constant-time byte comparison.

## Troubleshooting

- **Bridge unavailable:** Start Open Jarvis and its Overlay Service.
- **Config provider denied:** Ensure the installed Termux package is
  `com.termux` and restart Open Jarvis after installing Termux.
- **socat missing:** Run `pkg install socat` in Termux.
- **ADB connection fails:** Re-read the provider config and forward the exact
  reported port.
